## 2. Что важно знать владельцу

- **Скрипт из образа рекомендера удаляет данные в проде.** `export_event_log.py --retention-days 30` идёт host-cron'ом в 03:15 UTC через `docker compose run` с `SUPABASE_DB_URL`. Удаление аккуратное: по одному UTC-дню в транзакции, только если все три parquet-файла дня лежат в `--out`, минимум 2 дня, `identity_links` не трогает. Но: (а) parquet на диске сервера (`/opt/backend_sloco/exports`) — **единственная копия** event log после 30 дней, бэкапа с сервера нет; (б) сама cron-строка живёт на хосте, в репо её нет (как и `sloco-dashboard`, SLO-29). Оба пункта — в тему инфры.
- **Артефакты.** В `main` уже лежит ~190 MB артефактов (`locations_combined_food_ttd.csv` 94 MB, два `.npy` 77 + 15 MB) — это было до Кирилла. dev добавляет ещё 18 MB (`direct_place_image_embeddings_openclip_vitb32_v1.npy` + parquet) для каталога на 12.5k. **Не перенесено:** прод с `0f52e65` читает артефакты с хоста, репозиторные в образе инертны; тесты на них не завязаны. Политика «артефакты не в git» — SLO-19; там же решить судьбу уже лежащих 190 MB.
- **CSLS на большом каталоге.** Без `RECOMMENDER_HUBNESS_METHOD=none` в окружении v4 на 58k мест отвечает десятки секунд. Значение по умолчанию в коде — `csls`. Пока `docker-compose.yml` в `main` не перенесён (тема 1.3), деплоить `main` нельзя — рекомендер уйдёт в таймауты.
- `docs/README.md` рекомендера ссылается на `../../../recommender-config-audit.md` и `ios-asks-implementation-plan.md` — файлы из корня dev-репо, в `main` их нет до темы «доки» (1.5). Ссылки пока битые, сознательно.
- `Dockerfile` теперь копирует `scripts/` в образ (для экспортёра) — ок.
