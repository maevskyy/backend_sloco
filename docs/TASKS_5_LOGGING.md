# TASKS 5: Grafana Cloud Logging

## Goal

Move backend logs to Grafana Cloud Free using Grafana Loki, without
self-hosting Loki on the Lightsail server.

The MVP logging setup should:

- keep production logs structured;
- avoid eating server disk;
- provide a searchable UI in Grafana Cloud;
- keep local development logs readable and colored;
- avoid running a heavy observability stack on the 2 GB Lightsail instance.

## Decision

Use:

- Fastify/Pino for application logs.
- `pino-pretty` only in local development.
- Docker log rotation on the server.
- Grafana Cloud Free for log storage/search UI.
- Grafana Alloy on Lightsail as the log collector.

Do not self-host Loki for MVP.

Grafana Cloud Free currently includes managed logs with a free monthly
ingestion allowance and limited retention. Confirm current limits on the
official pricing page before relying on them long term:

```text
https://grafana.com/pricing/
```

Relevant Grafana docs:

```text
https://grafana.com/docs/grafana-cloud/monitor-infrastructure/integrations/integration-reference/integration-docker/
https://grafana.com/docs/loki/latest/api/
```

## Current Logging State

Fastify already uses Pino when configured with:

```ts
Fastify({
  logger: true
})
```

So the goal is not to replace logging from scratch. The goal is to configure it
properly for:

- pretty local logs;
- JSON production logs;
- safe Docker retention;
- shipping production logs to Grafana Cloud.

## Implementation Plan

### 1. App Logging

Add `pino-pretty` as a dev dependency.

Change Fastify logger configuration:

- `development`: pretty colored logs.
- `test`: quiet or disabled logs.
- `production`: JSON logs to stdout.

Expected behavior:

```text
local dev -> readable colored logs
tests     -> no scary expected-error noise
prod      -> structured JSON logs
```

Keep logs on stdout/stderr. Do not write app logs to files from Node.

### 2. Docker Log Rotation

Update production compose template:

```yaml
services:
  backend:
    logging:
      driver: json-file
      options:
        max-size: "10m"
        max-file: "3"
```

This keeps local Docker logs bounded to about 30 MB per container.

Apply the same change manually on the server in:

```text
/opt/backend_sloco/docker-compose.yml
```

Then restart:

```bash
cd /opt/backend_sloco
docker compose up -d backend
```

### 3. Grafana Cloud Setup

In Grafana Cloud:

1. Create or open Grafana Cloud account.
2. Create/select a stack.
3. Go to:

   ```text
   Connections -> Docker
   ```

4. Follow the Docker integration instructions.
5. Get the Loki endpoint and credentials.

Needed values:

```text
GRAFANA_CLOUD_LOKI_URL
GRAFANA_CLOUD_LOKI_USERNAME
GRAFANA_CLOUD_LOKI_TOKEN
```

The URL usually points to a Loki push endpoint or base Loki endpoint. Use the
exact endpoint Grafana Cloud gives in its Docker/Alloy instructions.

### 4. Install Grafana Alloy On Lightsail

Install Alloy on the Lightsail host using Grafana Cloud's generated
instructions from the Docker integration page.

Alloy should collect Docker container logs and ship them to Grafana Cloud Loki.

Alloy must be able to read Docker logs. Grafana's Docker integration docs may
ask to run Alloy with elevated permissions or as `root`.

Verify service:

```bash
sudo systemctl status alloy
sudo journalctl -u alloy -n 100 --no-pager
```

### 5. Alloy Labels

Keep labels low-cardinality.

Good labels:

```text
service=backend
env=production
host=lightsail
container=backend
```

Avoid high-cardinality labels:

```text
request_id
user_id
url_with_query
ip
```

These can still exist inside the log line JSON, but should not become Loki
labels.

### 6. Grafana Explore

In Grafana Cloud:

```text
Explore -> Loki
```

Useful starter queries:

```logql
{service="backend"}
```

```logql
{service="backend"} |= "error"
```

```logql
{service="backend"} | json | statusCode >= 500
```

Exact labels depend on the Alloy config generated by Grafana Cloud.

### 7. Verification

Generate backend traffic:

```bash
curl http://52.18.13.69/health
curl http://52.18.13.69/health/supabase
curl "http://52.18.13.69/map/places?city=Berlin&swLat=52.4800&swLng=13.3300&neLat=52.5600&neLng=13.4700&limit=100"
```

Check server logs:

```bash
cd /opt/backend_sloco
docker compose logs --tail=100 backend
```

Check Grafana Cloud Explore and confirm the same requests appear there.

## Acceptance Criteria

- Local development logs are pretty and readable.
- Test output no longer prints noisy expected-error logs.
- Production backend logs remain structured JSON.
- Docker log rotation is configured in the production compose template.
- Lightsail Docker logs are bounded after updating server compose.
- Grafana Cloud receives backend container logs.
- Grafana Explore can query backend logs.
- No Grafana tokens are committed.
