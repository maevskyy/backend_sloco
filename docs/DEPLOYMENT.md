# Backend Deployment

Production is deployed as one Docker Compose stack on one Hetzner host.

The production source of truth is:

```text
docker-compose.yml
.github/workflows/deploy-production.yml
```

The workflow ships stack files and renders `/opt/backend_sloco/.env` from GitHub
secrets. Normal deploys should not require manual `scp` or hand-editing `.env`.

## Server Directory

```text
/opt/backend_sloco/docker-compose.yml
/opt/backend_sloco/deploy/
/opt/backend_sloco/observability/
/opt/backend_sloco/.env
```

`/opt/backend_sloco/.env` is generated by CI/CD. It should not be treated as the
source of truth.

## GitHub Secrets

The backend monorepo owns one production secret contour.

Required for normal app deploys:

```text
DEPLOY_HOST
DEPLOY_USER
DEPLOY_SSH_KEY
PRODUCTION_API_URL
GHCR_USERNAME
GHCR_READ_TOKEN
SUPABASE_URL
SUPABASE_SERVICE_ROLE_KEY
SUPABASE_DB_URL
```

Required only when deploying/refreshing the self-hosted observability stack
(`with_observability=true`):

```text
GF_SECURITY_ADMIN_USER
GF_SECURITY_ADMIN_PASSWORD
GF_SERVER_ROOT_URL
```

`GF_SERVER_ROOT_URL` should be:

```text
https://grafana.sloco.pp.ua
```

Do not commit real secrets. `SUPABASE_SERVICE_ROLE_KEY` must stay server-side.
`SUPABASE_DB_URL` is the pooled Postgres connection string used by the gateway for
binary vector tiles (`/v1/map/tiles/...mvt`); use the Supabase pooler connection
string, not a public API URL.

## Deploy Flow

Manual workflow:

```text
.github/workflows/deploy-production.yml
```

Inputs:

- `service=all` builds and deploys gateway + recommender.
- `service=gateway` builds/deploys only the Gateway image and preserves the
  current recommender image tag.
- `service=recommender` builds/deploys only the recommendation image and
  preserves the current Gateway image tag.
- `ref` is the branch, tag, or commit SHA to deploy.
- `with_observability=true` also converges Loki, Prometheus, and Grafana. Leave it
  off for normal app-only deploys.

The workflow:

1. checks the selected service with build/test/lint/typecheck;
2. builds and pushes image tags to GHCR;
3. syncs stack files to `/opt/backend_sloco`;
4. renders `.env`;
5. runs app-only by default:

   ```bash
   docker compose pull
   docker compose up -d
   ```

   With `with_observability=true`, it runs:

   ```bash
   docker compose --profile observability pull
   docker compose --profile observability up -d
   ```

6. healthchecks `http://127.0.0.1:3000/v1/health` and the public API URL.

## Runtime Stack

Default application path:

```text
Nginx -> 127.0.0.1:3000 -> backend -> recommendation-service / Supabase / Redis
```

Observability path:

```text
Alloy -> 127.0.0.1:3100 Loki
Alloy -> 127.0.0.1:9090 Prometheus
Nginx -> 127.0.0.1:3001 Grafana
```

Redis is a normal service, not a profile-only optional dependency. The
observability services are converged when `with_observability=true`.

## Nginx And HTTPS

Host Nginx remains outside Docker.

Templates:

```text
deploy/nginx/backend_sloco.conf
deploy/nginx/grafana_sloco.conf
```

Public domains:

```text
https://sloco.pp.ua
https://grafana.sloco.pp.ua
```

HTTPS is managed on the server by Certbot + Let's Encrypt. Certbot owns the
server-side certificate paths under `/etc/letsencrypt`.

Nginx should proxy only intended public surfaces:

```text
sloco.pp.ua/v1/*       -> http://127.0.0.1:3000
grafana.sloco.pp.ua/*  -> http://127.0.0.1:3001
```

## Health Checks

Gateway:

```bash
curl http://127.0.0.1:3000/v1/health
curl https://sloco.pp.ua/v1/health
```

Recommendation service from inside the Docker network:

```bash
docker compose exec backend node -e "fetch('http://recommendation-service:8000/v1/health/ready').then(r=>r.text()).then(console.log)"
```

Redis:

```bash
docker compose exec redis redis-cli ping
```

Grafana:

```bash
curl -I http://127.0.0.1:3001
curl -I https://grafana.sloco.pp.ua
```

## Rollback

Rollback is image-tag based:

1. rerun the deploy workflow with a previous `ref`, or
2. manually set `BACKEND_IMAGE` / `RECOMMENDATION_SERVICE_IMAGE` in `.env` to a
   known good tag and run:

   ```bash
   docker compose pull <service>
   docker compose up -d <service>
   ```

Prefer workflow rollback once the monorepo deploy is stable.

## Logs

Local Docker logs are bounded by compose log rotation.

```bash
docker compose logs --tail=100 backend
docker compose logs --tail=100 recommendation-service
docker compose logs --tail=100 redis
docker compose logs --tail=100 grafana
```
