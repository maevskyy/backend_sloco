# Walk Planner messages and error codes — v1

Everything the Walk Planner tells the user is a **stable code** with **parameters**. Each code also comes with a
convenience text in Russian or English. This page lists every code. [API.md](API.md) describes where the codes
appear in responses.

| | |
|---|---|
| Source of truth | `walk_planner/messages.py` (`MESSAGES`, `ERRORS`: severity, scope, HTTP status, declared params, RU / EN renderers) |
| Machine-readable copy | [`messages.json`](messages.json), generated by `python tools/export_messages.py` (format `walk-messages/v1`); `--check` fails when it is stale, and the tests run that check |
| This page | the tables in §2 and §3 are generated from `messages.json` (API `v1`, algorithm `1.0.0`: 15 messages, 20 errors). If they disagree on a code, its params or texts, `messages.json` wins. Its prose `notes` are not part of that: one of them overstates which Russian texts are the dashboard's (§1.4) |
| Tests | `tests/test_messages.py`: the Russian texts of the dashboard codes equal the dashboard's strings byte for byte, and every golden response uses exactly the declared params |

## 1. How the app should use the catalog

### 1.1 Two kinds of codes

- **Messages** come inside 200 responses as `{code, severity, scope, params, stop_index, text}`:
  - `scope: "request"` in the plan's top-level `messages`;
  - `scope: "variant"` in `variants[i].messages` (and in `variant.messages` of edit responses);
  - `scope: "stop"` in the same list, with `stop_index` = the `Stop.index` it is about.
- **Errors** are the bodies of non-2xx responses: `{"error": {"code", "message", "params"}}`, with the HTTP status
  in the table. Their severity and scope are always `error`.
- `place_temporarily_closed` is both: a stop warning on a kept stop, and the 422 that asks the user to confirm an
  insert.

### 1.2 Localize from `code` + `params`

- **The app should render texts itself** from `code` and `params`. `text` (messages) and `message` (errors) are
  conveniences: they are already rendered in the request's `lang` (`ru` | `en`; default `WALK_DEFAULT_LANG` = `ru`)
  and can be shown as they are when the app has no translation of its own.
- **Unknown codes** (codes are append-only, new ones may come): show a message's `text` styled by its `severity`;
  handle an unknown error code by its HTTP status (4xx: show `message`; 503: retry after `Retry-After`).
- **Severity** of messages: `info` (neutral explanation), `warning` (the route has a problem the user should see),
  `error` (no route; only `no_candidates` / `no_route`, which come with `status` ≠ `ok`).

### 1.3 Params

Params hold raw values: numbers (minutes, km), codes, place ids and names, TimePoints and structured opening hours.
Some messages also carry **pre-formatted Russian clock labels** (`*_label`), which the Russian texts embed.

| Label param | Format | Use instead, when rendering yourself |
|---|---|---|
| `window_start_label` | `HH:MM` | `request.start_time` / `request.window_start` |
| `window_end_label` | `HH:MM`, plus ` (+1 день)` when the window ends after midnight | `request.window_end` (its date is the next day) |
| `finish_label` | `HH:MM`, plus ` (+N)` when N days after the departure day | `finish_at` (a TimePoint in the same params) |
| `arrival_label`, `departure_label` | `HH:MM`, plus ` (+N)` | `arrival` / `departure` of the stop at `stop_index` |
| `hours_label` | Russian hours at arrival, e.g. `сб 08:00–13:00`, `вс до 02:00, 10:00–00:00`, `пн закрыто` | `hours_day` (structured HoursDay, in the same params) |

- Activity codes (`activities`, `activity`), the `style` code and the `shape` code: take the labels from
  `GET /v1/walks/config` (`label_ru`, `label_en`).
- Place names (`name`, `names`) are catalog names, in the local language.
- The English texts turn ` (+1 день)` into ` (+1 day)`; ` (+N)` stays as it is.
- Labels round minutes with Python's `round` (half to even), like the dashboard.

### 1.4 Text status — what needs product sign-off

| Texts | Status |
|---|---|
| **Russian, 13 codes**: the messages `radius_shrunk`, `slots_no_candidates`, `no_candidates`, `no_route`, `fewer_variants`, `personalization_unavailable`, `extras_added`, `slots_dropped`, `over_budget`, `route_empty`, `stop_hours_conflict`; the errors `place_already_in_route`, `no_slots_or_must_visits` | The research dashboard's current strings, byte for byte ("dashboard" in the tables) |
| **Russian, 22 codes new in v1**: the messages `must_visit_closed_forever`, `unknown_place_ids`, `routing_estimate`, `place_temporarily_closed`; the other 18 errors | **Drafts: need product sign-off** before the app shows them. The insert confirmation «⛔ Временно закрыто по данным Google — всё равно добавить?» follows the UX test report (WP-04; research repo `recommendation_system/ai_location_recommender/WALK_PLANNER_UX_TEST_REPORT.md`) |
| **English, all 35** | **Drafts**, written during the v1 migration |

The `notes` of `messages.json` say that the Russian texts reproduce the research dashboard byte for byte. That
holds only for the 13 codes of the first row; the generator's wording is a known issue
([HANDOFF.md §4.2](HANDOFF.md#42-known-issues-in-the-packages-own-files)). This table is right.

Some "dashboard" Russian texts were written for the research dashboard. They are kept as they are in v1 (golden
parity) but need a product decision before the app uses them as is:

- `extras_added` ends with «выключите «Добавлять места по пути»», which names the dashboard's checkbox; the app's
  control may be called differently.
- `fewer_variants` suggests «число кандидатов на слот», a bench-only setting (`top_k`) the app does not have; the
  English draft drops that clause. It also appears for walks without slots, where it makes little sense (WP-42).
- `route_empty` says «перетащите что-нибудь обратно»: it assumes drag and drop.
- `personalization_unavailable`: the dashboard printed the exception text in brackets (`detail`). The service never
  sends `detail`, so its text is «⚠︎ персонализация недоступна; ранжирую по популярности.».
- Known wording defects from the UX test report (WP-42), kept in v1:
  - `stop_hours_conflict` says «оставьте, если знаете, что сегодня работает дольше» even on a day the place is
    closed all day (`params.closed_all_day`);
  - `radius_shrunk` (`overpacked`) says «это больше окна» when the visits merely equal the window, and «слоты,
    которые не влезут, отпадут» even when nothing was dropped;
  - `slots_dropped` blames the window when the real cause may be opening hours;
  - `slots_no_candidates` advises «увеличьте радиус» even when the service narrowed the radius itself.
- `validation_error` embeds the field and reason in English («Некорректный запрос: body.variants — Input should be
  less than or equal to 5.»): the request-format check (pydantic) only speaks English.

## 4. Parameters by code

### 4.1 Messages

**`radius_shrunk`** (info, request). The search radius was narrowed to what the window can reach.

| Param | Type | Meaning |
|---|---|---|
| `radius_km` | number | the requested radius |
| `search_radius_km` | number | the radius actually searched (= `request.search_radius_km`) |
| `reason` | `"reach"` \| `"overpacked"` | `reach`: you cannot walk further within the window. `overpacked`: the slots' typical visit lengths alone take the whole window or more. The text is variant (b) for `overpacked`, (a) otherwise |
| `dwell_total_min` | number | sum over the slots of the user's visit length, else the activity's typical length |
| `window_min` | integer | window length |
| `window_start_label`, `window_end_label` | string | Russian clock labels of the window ([§1.3](#13-params)) |
| `anchor` | `"start"` \| `"center"` | the search is around the start, or around the city centre (`free`). Changes «рядом со стартом» / «в центре района» |
| `loop` | boolean | shape `loop`: the walk must come back. Adds «, и нужно вернуться к старту.» |

**`slots_no_candidates`** (warning, request). `activities`: activity codes of the slots without any open place in the
radius; `slot_indices`: their indexes in `request.slots` (same order). Those slots are missing from every variant.

**`no_candidates`**, **`no_route`** (error, request). No params. They come with `status: "no_candidates"` /
`"no_route"` and no variants.

**`fewer_variants`** (info, request). `built` (integer): routes returned; `requested` (integer): `request.variants`.

**`must_visit_closed_forever`** (warning, request). `place_ids` (string[]) and `names` (string[], same order): the
permanently closed must-visit places that were left out.

**`unknown_place_ids`** (warning, request). `place_ids` (string[]): ids not in the city catalog, skipped; `field`
(string): where they came from, `"must_visit_place_ids"` in v1.

**`personalization_unavailable`** (warning, request). The plan uses popularity instead of the user's favourites
(`personalization.mode: "popularity"`).

| Param | Type | Meaning |
|---|---|---|
| `reason` | string | `"taste_unavailable"` (the bundle has no taste model), `"interest_module_unavailable"`, or `"interest_error:<ExceptionType>"`. A machine code, not shown in the text |
| `detail` | string, optional | **never sent by the service.** The research dashboard adds its own explanation when it renders the caption |

**`extras_added`** (info, variant; planner variants only, not after edits). `count` (integer ≥ 1): on-the-way stops
added; `style`: the style code (the text shows its label); `window_start_label`, `window_end_label`.

**`slots_dropped`** (warning, variant; planner variants only). `activities`: activity codes of the requested slots
that did not fit; `slot_indices`: their indexes in `request.slots` (= `summary.dropped_slot_indices`);
`window_end_label`.

**`over_budget`** (warning, variant). The route ends after the window (`summary.over_budget`).

| Param | Type | Meaning |
|---|---|---|
| `total_min` | number | the route's length (= `summary.total_min`) |
| `window_min` | integer | window length |
| `finish_label` | string | Russian clock label of the finish |
| `window_end_label` | string | Russian label of the window end |
| `finish_at` | TimePoint | the finish (= `summary.finish_at`) |

**`routing_estimate`** (info, variant). `segments_estimated` (integer): segments drawn as straight-line estimates;
`segments_total` (integer): all segments. It is present whenever at least one segment is an estimate, so it comes
with every variant that has segments when no street router is configured or reachable.

**`route_empty`** (info, variant). No params. An edited variant without stops (the user removed them all).

**`stop_hours_conflict`** (warning, stop; `stop_index` set). By the timetable the place is closed when the walker
arrives, or it closes before the visit ends. The stop is kept; the user may know better.

| Param | Type | Meaning |
|---|---|---|
| `reason` | `"closed_at_arrival"` \| `"closes_during_visit"` | = the stop's `hours.status`; picks text (a) or (b) |
| `place_id`, `name` | string | the place |
| `arrival_label`, `departure_label` | string | Russian clock labels of the stop's arrival and departure |
| `hours_label` | string | Russian hours of the arrival's weekday, e.g. `сб 08:00–13:00` |
| `closed_all_day` | boolean | no opening starts on the arrival's weekday. Then «оставьте, если знаете, что сегодня работает дольше» does not fit (WP-42): consider another text |
| `hours_day` | HoursDay | the structured hours at arrival ([API.md §4.10](API.md#410-hours)) |

**`place_temporarily_closed`** (warning, stop; `stop_index` set). `place_id`, `name`: a temporarily closed place that
is in the route anyway (a must-visit, or an insert the user confirmed).

### 4.2 Errors

| Code | Params |
|---|---|
| `validation_error` | Two shapes. The **request-format check** (pydantic) sends only `{"errors": [{"loc", "type", "msg", "input"?, "ctx"?}, ...]}`: `loc` is a path such as `["body", "slots", 0, "activity"]` or `["query", "lat"]`; `type` is pydantic's error type (`missing`, `string_pattern_mismatch`, `less_than_equal`, `json_invalid`, …); `input` is the offending scalar (strings cut to 100 characters). The message is built from the first problem. The **planner's and the service's own checks** send `{"field", "reason"}`, plus `value` (the rejected value), `place_id` (a stop twice in a sequence) or `available` (the cities, when `city` is required). `messages.json`'s second example shows both shapes in one object; the service sends one or the other |
| `unknown_city` | `city`: as sent; `available`: the served cities |
| `invalid_window` | `window_min`: the computed length (may be 0 or negative); `min`: 15; `max`: 1440 |
| `start_required` | `shape`: `loop` or `one_way` |
| `unknown_activity` | `activity`: as sent; `slot_index`: its slot; `allowed`: the activity codes |
| `duplicate_activity` | `activity`: the repeated code; `slot_index`: the slot of the repeat |
| `no_slots_or_must_visits` | none |
| `too_many_must_visits` | `count`: must-visit places after removing duplicates; `max`: 10 |
| `unknown_place` | `place_id`; `field`: where it was: `"place_id"` (insert, place screen), `"start.place_id"` (plan), `"sequence[<i>].place_id"` (edits) |
| `place_already_in_route` | `place_id` |
| `place_closed_forever` | `place_id`, `name` |
| `place_temporarily_closed` | `place_id`, `name`. Ask the user; resend `/insert` with `"allow_temporarily_closed": true` |
| `catalog_changed` | `place_id`: the stop that is gone; `catalog_version`: the bundle now served; `plan_catalog_version`: the bundle of the request echo. Re-plan ([API.md §5.5](API.md#55-errors-during-editing)) |
| `not_ready` | `state`: `starting` \| `failed` \| `stopping`. `Retry-After: 5` |
| `busy` | `max_concurrent`: the worker's limit (`WALK_MAX_CONCURRENT_PLANS`); `retry_after_s`: 2, as in the `Retry-After` header |
| `bad_request` | none |
| `not_found`, `method_not_allowed` | `path`: the requested path |
| `payload_too_large` | `max_bytes`: the limit (`WALK_MAX_BODY_BYTES`) |
| `internal_error` | `request_id`: the response's `X-Request-Id`; look it up in the service log (the stack trace is only there) |

## 5. Keeping this page current

- A new or changed code starts in `walk_planner/messages.py` (`MessageDef`: severity, scope, HTTP status, `params`,
  `optional`, `examples`, RU and EN renderers). Then run `python tools/export_messages.py` to rewrite
  `docs/messages.json`; the tests fail until it is current.
- §2 and §3 above are generated from `messages.json`: regenerate the two tables, keep the "RU status" column
  ("dashboard" only for the 13 codes in §1.4), and add the new code's params to §4.
- Codes are append-only: never rename or reuse one. Texts and params are part of the golden outputs, so changing
  any of them is at least a MINOR version (`walk_planner/version.py`); changing a "dashboard" Russian text also
  changes what the research dashboard shows.
